## Слайд 1 — Титул

Тема: **psql**. Единственный клиент, который всегда есть «в коробке» с Postgres.

Факт на старт: DBeaver/DataGrip/pgAdmin могут отвалиться, пропасть с машины
или не поставить на прод-хост. `psql` — нет. Это ваш аварийный люк.

## Слайд 2 — Темы занятия

Четыре блока:

1. Запуск и подключение  
2. Справка (`\?`, `\h`)  
3. Работа: SQL, форматы, переменные, скрипты  
4. Настройка (`.psqlrc`)

Демо одно плотное — там основная мясорубка. Потом практика.

## Слайд 3 — Назначение

`psql` = терминальный фронтенд к PostgreSQL.

- идёт **в поставке СУБД** (не сторонний тул);
- и для интерактива, и для скриптов (`-f`, `< file`, `\i`);
- админы и разработчики — одна аудитория.

Интересный момент: meta-команды psql (всё с `\`) обрабатывает **клиент**,
а SQL уходит на **сервер**. Поэтому `\d` может работать даже там,
где GUI ещё не нарисовал схему.

Доки: https://postgrespro.ru/docs/postgresql/16/app-psql

## Слайд 4 — Подключение

```bash
psql -d база -U пользователь -h узел -p порт
```

Внутри сессии:

```text
\c[onnect] база пользователь узел порт
\conninfo
```

**Дефолты, если ничего не указать** (частый сюрприз для новичков):

| параметр     | дефолт                          |
|--------------|---------------------------------|
| база         | = имя пользователя              |
| пользователь | = имя пользователя ОС           |
| хост         | Unix-socket (не TCP!)           |
| порт         | обычно 5432                     |

Факты:

- `-h localhost` и без `-h` — **разные пути**: TCP vs socket. Права в `pg_hba.conf` тоже разные.
- `\c` без аргументов переподключается к текущим параметрам; незаданные берутся из **текущего** коннекта, не из «дефолтов ОС».
- Пароль можно не светить: `~/.pgpass`, сервисный файл, переменные `PG*` (libpq).

Полезные ссылки (наговорить, не читать вслух целиком):
- env: https://postgrespro.ru/docs/postgresql/16/libpq-envars  
- service: https://postgrespro.ru/docs/postgresql/16/libpq-pgservice  
- pgpass: https://postgrespro.ru/docs/postgresql/16/libpq-pgpass

## Слайд 5 — Получение справки

В шелле:

```bash
psql --help
man psql
```

Внутри psql:

| команда        | что даёт                    |
|----------------|-----------------------------|
| `\?`           | список команд psql          |
| `\? variables` | переменные psql             |
| `\h`           | список SQL                  |
| `\h CREATE TABLE` | синтаксис конкретной команды |
| `\q`           | выход (`exit`/`quit` тоже)  |

Факты:

- Команды psql почти всегда можно **сокращать**: `\connect` → `\c`, `\help` → `\h`.
- `\h` берёт справку **с сервера** (версия сервера важна: синтаксис 16-го ≠ 12-го).
- `\?` — про клиент. Путать `\h` и `\?` — классика первых дней.

## Слайд 6 — Демонстрация

Четыре пункта на слайде — проговорить быстро и показать руками.

### 1. SQL

- SQL может быть **многострочным**; на сервер уходит после `;`.
- Команды psql — обычно **одна строка**, начинаются с `\`.

```sql
SELECT schemaname, tablename, tableowner
FROM pg_tables
LIMIT 5;
```

### 2. Форматирование

| команда / фича | зачем |
|----------------|--------|
| `\a` | aligned ↔ unaligned |
| `\t` | спрятать заголовок и footer `(N rows)` |
| `\x` | expanded: столбец=строка (спасение при широких таблицах) |
| `\gx` вместо `;` | expanded **только для этого** запроса |
| `\pset` | все крутилки; без аргументов — dump текущих настроек |
| `\pset fieldsep ' '` | разделитель в unaligned |

Лайфхак: `SELECT ... \gx` — не надо включать `\x` глобально и потом забывать выключить.

Пайпы и файлы:

```text
\! pwd                    -- shell из psql
\o file                   -- весь вывод в файл; снова \o — обратно на экран
\g | cat -n               -- результат в pipe ОС
\g file                   -- результат в файл
\i file                   -- выполнить скрипт
\gexec                    -- каждая ячейка результата = SQL и выполнить
```

Факт про `\gexec`: сгенерировали `SELECT count(*) FROM ...` через `format('%I', ...)`,
потом `\gexec` — и psql сам прогнал пачку. Бедный человек DDL-миграций оценит.

### 3. Переменные

```text
\getenv User USER
\set Test Hi
\echo :Test :User!
\unset Test
SELECT now() AS curr_time \gset   -- одна строка результата → :curr_time
\set                              -- dump всех переменных
```

Условия в скриптах:

```text
\if :{?working_dir}
\else
\set working_dir `pwd`
\endif
```

`:{?var}` → TRUE/FALSE «переменная задана». Обратные кавычки = подстановка вывода shell.

Встроенные, на которые стоит ткнуть пальцем в `\set`:
`DBNAME`, `USER`, `HOST`, `PORT`, `AUTOCOMMIT`, `PROMPT1`, `ON_ERROR_ROLLBACK`, `ERROR`, `SQLSTATE`.

Каталог объектов (спойлер на потом): `\d`, `\dt`, `\di`, `\l+` — серия `\d*`.

### 4. `.psqlrc`

При старте (если файлы есть):

1. системный `psqlrc` — путь: `pg_config --sysconfdir` (в Ubuntu часто `/etc/postgresql-common`);
2. пользовательский `~/.psqlrc`.

По умолчанию **оба отсутствуют** — пустой старт не баг.

Пример в сессии / в rc:

```text
\set top5 'SELECT tablename, pg_total_relation_size(schemaname||''.''||tablename) AS bytes FROM pg_tables ORDER BY bytes DESC LIMIT 5;'
:top5
```

Ещё: readline → автодополнение и история; крутятся через `HISTFILE`, `HISTSIZE`.

## Слайд 7 — Итоги

Коротко:

- `psql` — штатный терминальный клиент;
- на входе нужны параметры коннекта (или сработают дефолты — знайте их);
- два мира команд: **SQL** и **`\`-команды**;
- годится и для руками, и для скриптов (`\i`, `-f`, переменные, `\if`).

Если забрали только три команды на память: `\conninfo`, `\?`, `\x` / `\gx`.

## Слайд 8 — Практика

Задачи со слайда — с конкретными ответами (чтобы подсказывать, не спойлерить сразу):

1. `psql` → `\conninfo`  
2. `\l+` — подробный список БД (size, tablespace, description)  
3. Pager: в `.psqlrc`  
   `\setenv PSQL_PAGER 'less -XS'`  
   Зачем `-XS`: без wrap длинных строк + не стирать экран при выходе из less.  
   Важно: `PSQL_PAGER`, не обязательно глобальный `PAGER` — чтобы не ломать less во всей ОС.
4. Prompt `user@db=#`:  
   `\set PROMPT1 '%n@%/%R%x%# '`  
   и то же в `PROMPT2`  
   (`%n` user, `%/` db, `%R` статус, `%x` транзакция, `%#` `#` или `>`).
5. `\timing on` → в `~/.psqlrc`, иначе после `\q` пропадёт.

Итоговый `.psqlrc` из решения курса:

```text
\setenv PSQL_PAGER 'less -XS'
\set PROMPT1 '%n@%/%R%x%# '
\set PROMPT2 '%n@%/%R%x%# '
\timing on
```

После правок rc — перелогин в psql (`\q` и снова `psql`).

Факт: в приглашении `*` = открыта транзакция, `!` = транзакция aborted после ошибки.
Это пригодится на следующем слайде.

## Слайд 9 — Практика+

Суть эксперимента:

**По умолчанию** после ошибки внутри `BEGIN` сервер говорит:
`current transaction is aborted, commands ignored until end of transaction block`.
Дальше только `ROLLBACK`/`COMMIT` (оба выльются в rollback). Частичного undo одной команды Postgres **не умеет**.

**`\set ON_ERROR_ROLLBACK on`** — трюк **клиента**:
перед каждой командой psql ставит `SAVEPOINT`, при ошибке откатывается к нему.
Сервер как будто «съел» только плохую команду; транзакция жива.

Ещё значение: `ON_ERROR_ROLLBACK = interactive` — автосейвпоинты только в интерактиве, не в скриптах.
В скриптах автоматом маскировать ошибки обычно опасно.

Мини-сценарий:

```sql
BEGIN;
CREATE TABLE t (id int);
INSERTINTO t VALUES(1);   -- ошибка
-- без ON_ERROR_ROLLBACK: всё, тупик
-- с on: можно INSERT INTO t VALUES(1); и COMMIT;
```

Не тащите `ON_ERROR_ROLLBACK=on` в прод-скрипты миграций бездумно:
удобно руками, в CI лучше явный fail.

Уборка: `\set ON_ERROR_ROLLBACK off`, `DROP TABLE t`.
